Factotum

Sep 2026 – present · in active development

A self-hosted voice assistant that answers from your own documents, performs actions on your devices, and runs on the models you choose.

Speakers with a microphone (a PC or a Raspberry Pi) connect to the system over a WebSocket. A person talks by pressing a key or saying a wake word; speech streams in, is transcribed, answered from the user's documents with retrieval-augmented generation, and the spoken answer streams back sentence by sentence. Every model — chat, embeddings, speech-to-text, text-to-speech — is chosen by the user: a local model through Ollama, or a hosted provider with their own key.

What I built

  • Model gateway — one normalized API for chat (streaming, structured output), embeddings, speech and web search over OpenAI, Anthropic, Gemini, Ollama and OpenAI-compatible servers, with retries, timeouts, typed errors and redaction. No other service names a model.
  • Knowledge service — ingests text, Markdown, HTML, PDF and Word; chunks into searchable pieces and readable sections; hybrid retrieval (vector + full-text) in Postgres/pgvector that degrades instead of failing. Measured on a 931-page book: ~3,000 pieces indexed in under two minutes on a consumer GPU.
  • Conversation service — answers a turn with citations, streamed, with no history carried along: past turns are searched only when a message refers to them, keeping prompts small for local models.
  • Actions & skills — a skill is a Markdown document with optional code and declared permissions. The model proposes, the code decides: a policy engine checks who the device acts for, the device's policy and the skill's targets; confirmations and approvals fail closed; every action lands in an audit trail.
  • Sandboxed execution — each skill run gets a throwaway container whose only way out is an egress proxy that enforces a signed grant of reachable hosts, checking every resolved address.
  • Voice pipeline — wake word on the device (openWakeWord), audio streamed to the edge with barge-in, local speech-to-text (faster-whisper) and text-to-speech (Piper) through the gateway, audio streamed back and played as it arrives.
  • Identity — tenants, users, signed tokens every service verifies on its own, long-lived device pairing credentials. Permissions never depend on a voice.

WAV

A collaborative project management platform with hierarchical permissions and real-time updates, built as stateless microservices that scale horizontally.

Work is organized as Organization → Project → recursive Layers → Tasks → Comments, with custom Kanban boards at organization or team level. Every node of the hierarchy has its own membership; a user's effective role is resolved by inheritance with override — the most specific role along the chain wins.

What I built

  • Multi-level RBAC — owner / admin / editor / reader roles on organizations, projects and nested layers, assignable to users or teams, resolved by inheritance with override; permission checks cached in Redis.
  • Real-time collaboration — every mutation publishes an event; a WebSocket gateway bridges Redis Pub/Sub to connected clients, so writes never block on notification.
  • Reliable background jobs — a worker consumes Redis Streams for audit and notifications, with retries and dead-letter handling for stuck jobs.
  • Security hardening — JWT access/refresh, login rate limiting and lockout, soft-delete and deactivation, HTTPS everywhere; an audit that found and fixed 9 unauthenticated endpoints.
  • Deployment — Docker Compose for the prototype, Kubernetes manifests with Horizontal Pod Autoscalers and metrics-server, automated Let's Encrypt certificates via certbot, a cloud-init setup for an Oracle Cloud VM.
  • Testing & CI — pytest suites per service, Playwright system tests run against the deployed Kubernetes stack, GitHub Actions on every push.
